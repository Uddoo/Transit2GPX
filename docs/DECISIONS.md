# 关键设计决策

本文件记录已经接受的架构决策。实现中若要改变，必须同时更新相关契约、测试和路线图。

## D-001：本地优先的 Web 应用

**决定**：React 前端配合 FastAPI 本地服务，生产模式由单一 FastAPI 进程托管 API 和静态构建。

**理由**：地图和批量审核适合 Web UI；Python 地理生态成熟；本地运行能保护旅行历史并避免维护云端服务。

**代价**：需要协调前后端构建，并解决本地 Python/原生地理依赖的安装与打包。

## D-002：以 routes + stops 重建 route-aware edge

**决定**：不把发布的 `metro_segments` 当作唯一主路径表。首要输入是线路几何和线路站点，并构建保留 route variant、方向和支线语义的 `route_edge`；segments 用于校验和兜底。

**理由**：仅凭起终点段无法稳定区分共享换乘站、环线方向和支线。

**代价**：导入器复杂度上升，需要处理投影误差、线路方向和异常几何。

## D-003：全链路 WGS‑84，计算时局部米制投影

**决定**：存储、API 与导出统一 WGS‑84；几何长度、站点投影、切割和加密使用线路局部 AEQD。

**理由**：GPX 1.1 使用 WGS‑84；直接在经纬度上做米制运算会产生错误。

**代价**：每条线路需要显式坐标转换，且必须严格管理坐标顺序。

## D-004：歧义不得静默解析

**决定**：环线两方向、多个 route variant、模糊同名站、无线路全网规划等场景返回候选供用户确认。

**理由**：产品要记录真实历史，不是推荐理论最短路。

**代价**：部分输入需要多一步审核，CSV 流程也必须提供逐行修复界面。

## D-005：CSV 一行是一段实际乘坐线路

**决定**：换乘行程拆成多个 leg，每行必须有自己的线路、起点和终点。

**理由**：只记录旅程总起终点会让自动规划器选择用户没有乘坐的线路。

**代价**：输入较详细，但结果更可信和可复现。

## D-006：保存 edge 快照引用，不在导出时重算

**决定**：确认候选后保存有序的 `journey_leg_edge` 及方向。导出直接消费这些 edge。

**理由**：保证预览与输出一致，并防止数据/算法更新后历史行程静默变化。

**代价**：需要保留旧数据版本或提供显式迁移机制。

## D-007：SQLite + FTS5 + RTree

**决定**：v1.0 使用 SQLite 保存业务与几何 WKB，用 FTS5 做名称搜索、RTree 做空间范围查询。

**理由**：单用户本地应用不需要独立数据库服务，SQLite 易备份且支持所需索引。

**代价**：空间能力由应用层维护，不能依赖 PostGIS 的完整函数集。

## D-008：GPX 不伪造时间

**决定**：只有乘车日期时不生成逐点 `<time>`；默认也不生成海拔和速度。

**理由**：这些值无法从线路几何可靠推导，伪造会误导下游工具。

## D-009：两种导出语义

**决定**：提供 journey 模式和 coverage 模式。前者保留行程结构，后者按 edge 去重，更适合 Fog of World 补雾。

**代价**：coverage 模式必须重新分组连续 edge，不能把不相邻区间写进同一 `trkseg`。

## D-010：首版只保证 CPTOND，不强依赖在线增量源

**决定**：高德、OSM 或其他更实时来源属于后续 adapter，不作为 v1.0 完成条件。

**理由**：先把可验证、许可明确的数据导入和审查流程做完整，避免同时承担在线 API、坐标逆变换和来源融合风险。

## D-011：真实数据不入库，合成夹具入库

**决定**：仓库只保存小型合成或许可允许的裁剪测试夹具；完整 CPTOND 数据位于用户应用数据目录并有可复现导入流程。

**理由**：控制仓库体积，保持版本历史干净，并强迫 importer 对外部数据做完整验证。

## D-012：真实底图与线路数据分层

**决定**：地图画布使用 Leaflet。默认交互底图为 OpenStreetMap Standard raster tiles；瓦片 URL、署名、最大缩放级别和是否启用均由服务端运行时配置。线路与站点只渲染 `/api/v1/cities/{city_id}/map` 返回的 CPTOND GeoJSON，前端不得合成或装饰性绘制地铁几何。

**理由**：底图负责道路、街区和真实地理背景，CPTOND 负责可追溯的地铁语义。数据未导入、查询失败或范围为空时，保留底图并展示明确状态比伪造路径更可信。

**约束**：遵守 OpenStreetMap Foundation 的 Tile Usage Policy：地图内保持可见署名、仅按当前视口交互加载、尊重浏览器缓存、不提供瓦片预取或离线批量下载。在线瓦片会把视口请求发送给外部供应商，因此设置页必须披露并允许关闭或切换至自托管服务。

- https://leafletjs.com/reference.html#tilelayer
