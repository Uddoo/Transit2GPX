# 产品需求文档

## 1. 产品定义

Transit2Fog 帮助已经乘坐过中国地铁或国铁的用户，把地铁区间或铁路乘车事实还原成沿真实线路几何的轨迹，并导出到 Fog of World。

它不是通勤导航器，也不是替用户推测旅行历史的工具。产品的核心价值是：在来源可追溯、路径可预览、歧义可审核的前提下，批量生成精确、可复现的 GPX。

原 Metro2Fog v1.0 已完成地铁范围验收；铁路 R0–R3 随后完成并通过实机导入，产品现已扩展为地铁 + 国铁的 Transit2Fog。铁路详细设计见 [`RAILWAY.md`](RAILWAY.md)。

## 2. 目标用户与问题

主要用户是需要补录地铁、隧道等 GPS 丢失轨迹的 Fog of World 用户。他们通常拥有以下一种输入：

- 记得某次乘坐的城市、线路和起终点。
- 有多段换乘行程，希望逐段录入。
- 有几十到上百条历史记录，希望通过 CSV 批量处理。
- 已经导入过一部分区间，希望只导出新增覆盖。

现有手动画线方式不适合大量历史记录，也难以准确沿地下线路走向；普通最短路又可能选中用户没有实际乘坐的线路。

## 3. 产品目标

### 3.1 v1.0 必须实现

1. 可导入并校验 CPTOND-2025 的地铁线路与站点数据。
2. 可按城市、线路、起点、终点手动创建一段实际乘车记录。
3. 可在地图上选站并预览完整线路几何。
4. 可通过 UTF-8/UTF-8-SIG CSV 批量导入多段行程。
5. 可识别并展示环线、支线、同名站和模糊名称等歧义。
6. 只有明确解析或经用户确认的记录才能提交为行程。
7. 可浏览、筛选、编辑或删除本地行程。
8. 可按“保留每次行程”或“区间覆盖去重”两种模式导出 GPX 1.1。
9. 导出前执行结构、坐标范围、连续性和数据质量校验。
10. 在桌面宽屏与窄屏布局中完成核心流程，且可用单一启动入口运行。

### 3.2 成功标准

- 对受支持的普通线路，唯一明确的输入无需人工干预即可得到正确区间。
- 任一存在多条合理路径的输入都不会被静默提交。
- 地图预览、已保存行程和 GPX 导出使用相同的 `route_edge` 集合。
- GPX 通过官方 GPX 1.1 XSD 校验，且不包含跨换乘点或跨行程的错误直线。
- 同一数据版本和同一输入得到稳定结果。
- 用户无需将乘车记录上传到第三方服务。

### 3.3 铁路扩展目标

铁路首版在不回归地铁能力的前提下实现：

1. 从 Geofabrik/OSM PBF 构建版本化的本地铁路图。
2. 接受日期、车次、上下车站、有序经停站和线路提示等用户事实。
3. 通过 OpenRailRouting + 中国国铁 Profile 返回最多三个可解释候选。
4. 所有候选都经过地图确认；低置信候选不得直接保存或导出。
5. 保存带数据/图/Profile 版本的不可变 WGS‑84 几何快照。
6. 铁路默认按 200 米最大点间距生成 GPX，并保留 OSM 署名。
7. 地铁数据已就绪但铁路 sidecar 未安装时，地铁流程仍能独立运行。

铁路能力不提供售票、实时运行图或自动抓取 12306；车次类别只影响路径偏好，不能单独证明实际轨道。

## 4. 核心用户流程

### 4.1 首次设置

1. 打开应用，看到数据未就绪状态。
2. 选择 CPTOND 数据目录或执行受支持的下载/导入流程。
3. 应用检查必要文件、CRS、字段、版本与许可信息。
4. 导入器构建本地拓扑、搜索索引与质量报告。
5. 只有通过门禁的城市和线路进入可用状态。

### 4.2 手动或地图录入

1. 选择城市和线路。
2. 通过搜索框或地图选择起点、终点。
3. 可选填写日期、方向、途经站和备注。
4. 应用返回一个或多个候选，展示线路、方向、站数、距离、警告和地图形状。
5. 唯一无歧义候选可直接确认；多候选必须由用户选择。
6. 确认后保存行程及其固定 edge 列表。

### 4.3 CSV 批量录入

1. 上传 CSV，应用检测 UTF-8 或 UTF-8-SIG 编码并解析表头。
2. 每一行独立规范化和匹配，分为 `resolved`、`needs_review`、`unresolved`。
3. 用户可筛选问题行、修改字段、选择候选或忽略行。
4. 提交前展示将创建的 journey/leg 数量和仍未解决的问题。
5. 只提交已解析行；整个提交过程使用数据库事务。

### 4.4 导出

1. 按城市、线路、日期或行程筛选。
2. 选择普通模式或覆盖去重模式，并选择最大点间距。
3. 应用展示轨迹数、区间数、距离、数据版本和警告。
4. 校验通过后下载 `.gpx`。
5. 界面提示用户在 Fog of World 导入前创建数据快照，但不声称已代替 Fog of World 完成导入。

### 4.5 铁路录入与确认

1. 用户切换到铁路模式，填写日期、车次、上下车站和已知经停站，或粘贴有序站名列表。
2. 应用匹配本地 OSM 铁路站点；同名或低置信匹配要求用户确认。
3. Railway Provider 调用本机 OpenRailRouting sidecar，按完整站序生成 1～3 个候选。
4. 候选展示距离、高速/主线比例、经停站覆盖、置信度、警告和地图形状。
5. 用户确认后，服务端保存不可变铁路几何快照；再次打开和导出不重新算路。
6. 只有起终点、缺少日期或低于阈值的输入不能静默提交。

## 5. 功能需求

### 5.1 数据管理

- 展示数据源、版本、采集时间、许可、校验和、导入时间和 schema 版本。
- 支持重新导入和版本并存；旧行程仍能追溯原始版本。
- 提供按城市、线路和问题类型聚合的质量报告。
- 原始线路/站点无法可靠关联时进入人工审核或禁用状态。

### 5.2 搜索与名称匹配

优先级：

1. 城市 + 线路 + 中文站名精确匹配。
2. 已记录别名精确匹配。
3. 英文名精确匹配。
4. 拼音全拼与首字母匹配。
5. 中文模糊匹配。

建议初始阈值是唯一候选分数 `>= 95` 自动解析，`85–94` 进入审核，低于 `85` 未解析；阈值必须可配置并由真实数据测试校准。

### 5.3 路径解析

- 指定线路时，只考虑同时包含起终点的线路变体。
- 使用方向和途经站过滤环线/支线候选。
- 未指定线路时可给出带换乘的候选，但不能自动提交。
- 反向乘坐时，edge 顺序和每条几何坐标都必须反转。
- 候选结果携带数据版本、edge ID、质量标志和稳定摘要。

### 5.4 行程管理

- 一次行程可包含多个按 `leg_no` 排序的换乘分段。
- 行程记录日期、来源类型、备注和创建时间。
- 支持查看、编辑元数据、重新解析、删除和批量选择。
- 路径数据变化时不静默改写旧行程；需要显式迁移/重算。

### 5.5 GPX 导出

- 普通模式：一个 journey 对应一个 `trk`，一个 leg 对应一个 `trkseg`。
- 覆盖模式：每个已乘坐 `route_edge` 只导出一次，并避免把不连续 edge 连接成直线。
- 默认最大点间距 25 米，可选 15 米、50 米或保留原始折点。
- 默认不生成逐点 `<time>`，因为只有乘车日期不能推出真实时间。
- 输出包含应用名、数据源和数据版本，但不泄露本地绝对路径。

### 5.6 铁路 Provider

- 地铁与铁路共用 journey、审核、候选确认和导出外壳，路径解析由 Provider 分流。
- 铁路主几何只能来自已版本化并通过质量门禁的本地 OSM PBF/graph。
- OpenRailRouting 仅监听 loopback，前端不得绕过 FastAPI 直接访问。
- 有序经停站是硬约束；车次类型、线路提示和 OSM route 关系是评分特征。
- GraphHopper 内部 edge ID 不是历史主键；确认时保存完整几何、来源引用和摘要。
- 默认只提供手动和 CSV 时刻表 Provider；第三方在线 Provider 必须先通过许可审查。

## 6. 页面与导航

v1.0 采用五个主要页面：

- **行程**：行程列表、筛选、批量选择、编辑与删除。
- **添加行程**：城市/线路/起终点表单与地图联动、候选确认。
- **CSV 导入**：文件选择、逐行状态表、问题修复和事务提交。
- **导出**：范围、模式、点密度、统计、警告和下载。
- **数据与设置**：数据版本、导入进度、质量报告、署名和本地配置。

地图是核心工作区，但所有地图操作都必须有键盘可达的表单替代路径。

铁路扩展沿用五页信息架构：“添加行程”增加地铁/铁路模式与站序编辑；“数据与设置”分别展示 CPTOND 和 OSM/graph 状态；CSV、行程和导出页面按 mode 统一筛选，不新增平行的一套铁路页面。

## 7. 状态与错误体验

- 无数据时给出明确设置入口，不展示空白地图。
- 导入过程显示阶段、进度、成功/警告/失败计数，可安全重试。
- `needs_review` 必须说明“为什么需要确认”，而不只显示状态码。
- 导出被阻止时列出具体行程或线路及修复入口。
- 破坏性操作要求确认；批量删除显示数量和筛选范围。

## 8. 非功能需求

- **隐私**：应用数据仅本机存储并监听 loopback；不包含遥测。默认在线底图会向瓦片供应商发送当前视口的网络请求，必须显示署名与披露，并允许关闭或切换供应商。
- **可靠性**：数据导入和 CSV 提交事务化，失败可回滚。
- **性能**：按城市/视口加载；10,000 站级数据不能一次全部渲染。
- **铁路资源隔离**：区域图先行基准；全国图构建必须可观察、可取消并与 FastAPI 生命周期解耦，不能让地铁启动被长时间建图阻塞。
- **可访问性**：键盘操作、可见焦点、语义标签、非颜色唯一编码。
- **可测试性**：几何、匹配、导出为纯服务层；API 和 UI 有自动测试。
- **可迁移性**：macOS 为首个支持平台，架构不依赖专有桌面 API。

## 9. v1.0 明确不做

- 不直接控制或修改 Fog of World 的私有数据库。
- 不声称自动判断用户真实乘坐过哪条线路。
- 不把高德实时 API、OSM 或其他在线源作为 v1.0 必需依赖。
- 不生成伪造的逐点时间、速度或海拔。
- 不提供账户、云同步、多人协作或公开分享服务。
- 不把公交、铁路、航班扩展纳入首版验收。

## 10. v1.0 之后的铁路范围

铁路扩展已按长三角 POC、共享领域与单条行程、CSV/行程管理、全国数据运维四个阶段交付。真实路径、GPX XSD、Fog of World 实机导入和 metro-only 回归验收通过后，产品已从 Metro2Fog 迁移为 Transit2Fog。

具体数据模型、API、候选规则、许可与验收清单以 [`RAILWAY.md`](RAILWAY.md) 为准。
