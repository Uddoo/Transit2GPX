# 交付路线图

最后更新：2026-08-31。

- 铁路 R0–R3 已完成实现、自动化和实机验收，包括长三角与全国真实图、三套国铁 Profile、共享 Provider/行程模型、车站与站序审核、可解释候选、不可变快照、统一 CSV、混合 GPX、版本比较、显式重算、原子切换与回滚。
- 全国铁路图的当前验证基线包含 645,361 个节点、742,281 条边和 18,490 个车站索引；8 条代表性线路通过固定样本验证。铁路 GPX 已在 Fog of World 中完成手动导入验证，证据见 [`RAIL_FOG_ACCEPTANCE.md`](RAIL_FOG_ACCEPTANCE.md)。

- 工程优化第三、第四批已落地：行程服务端分页与批量加载、铁路 FTS5、地图 RTree 预筛、可重启恢复的 SQLite 持久化任务执行器、API 服务层以及跨平台统一任务入口。
- 工程优化第五批已落地：五个前端业务路由懒加载与 chunk 预算门禁、Windows/macOS 可复现安装产物及 smoke test、FastAPI 生命周期内的 OpenRailRouting sidecar 自动启动/身份验证/回收。

Fog of World 是当前有实机证据的兼容应用之一。产品的通用输出边界是 WGS‑84 GPX 1.1 `<trk>` / `<trkseg>`；原则上可导入任何支持该轨迹结构的应用，具体点数限制、简化和去重行为需按目标应用验证。

## 1. 交付策略

路线图按“每一阶段都能验证一个纵向能力”组织。阶段完成必须包含实现、测试、文档和可观察的验收结果；不能把数据质量、错误体验或打包留到最后才处理。

## 2. 阶段

### M0：工程基线

- 建立 backend/frontend 目录、依赖锁定、统一任务入口和环境示例。
- FastAPI `/healthz`、React 应用 shell、开发代理和生产静态托管跑通。
- 配置 lint、类型检查、pytest、Vitest 和最小 Playwright smoke test。
- 建立 SQLite engine、Alembic 和临时测试数据库夹具。

**验收**：全新 checkout 按 README 命令可启动；CI 等价检查本地全绿；生产构建能由单一服务打开。

### M1：数据模型与合成网络

- 实现 dataset/city/line/variant/station/stop/edge 和质量状态模型。
- 实现 WGS‑84/AEQD 转换、普通线路 edge 构建和反向几何。
- 构造覆盖普通线、环线、支线、换乘、同名站和异常几何的合成夹具。
- 实现 FTS5/RTree 初始化和重建。

**验收**：合成城市可导入；每类拓扑有确定的自动测试；错误线路被质量门禁阻止。

### M2：CPTOND 导入器

- 审计 CPTOND-2025 v2 实际目录、字段和 CRS，形成版本化 adapter。
- 实现文件发现、字段映射、名称规范化、站点聚类、route-stop 关联。
- 实现普通线路、环线和支线 edge 构建及 segments 交叉验证。
- 实现 staging、进度、取消、失败回滚和质量报告。
- 记录来源、许可、checksum 和署名。

**验收**：至少以一个普通线路城市和一个含环线/支线城市的真实数据完成导入与抽样校验；重复导入可复现；失败不会污染 active dataset。

### M3：查询、匹配与路径 API

- 实现城市、线路、站点、搜索和地图 API。
- 实现中文/英文/拼音/别名匹配和可配置分数阈值。
- 实现指定线路候选、方向/途经站过滤和反向 edge。
- 实现 `(station, line)` 状态图的未指定线路候选，始终要求确认。
- 对 API 契约和错误码建立集成测试。

**验收**：普通唯一路径自动解析；环线/支线/模糊同名输入返回可解释候选；所有候选有稳定 digest 和完整 GeoJSON。

### M4：行程录入与地图体验

- 实现响应式应用 shell、数据未就绪状态和主要导航。
- 实现城市/线路/起终点联动搜索与键盘操作。
- 实现地图线路/站点显示、点击选站、候选叠加与视口加载。
- 实现候选卡、质量警告、确认和 journey/leg/edge 事务保存。
- 实现行程列表、详情、筛选、元数据编辑、重算与删除。

**验收**：用户能从空表单完成“选择—预览—确认—保存—再次查看”；桌面和窄屏均可操作；预览与保存 edge 一致。

### M5：CSV 导入与审核

- 实现模板下载、UTF-8/UTF-8-SIG 解析、列/值校验和安全限制。
- 实现 batch/row 状态、分页、筛选、逐行修复、候选选择和忽略。
- 实现显式的提交策略、事务写入和汇总报告。
- 覆盖换乘分组、缺失线路、重复 leg、非法日期、公式字符串和大文件边界。

**验收**：示例 CSV 可生成两段换乘行程；问题行有明确原因和修复入口；提交失败可完整回滚。

### M6：GPX 导出

- 实现筛选与导出预览统计。
- 实现 journey 和 coverage 两种分组。
- 实现米制几何加密、反向拼接、重复点清理和不连续分段。
- 实现 GPX 1.1 XML、来源元数据和安全文件名。
- 集成 XSD、范围、最小点数、跳跃距离与确定性测试。

**验收**：两种模式输出通过 GPX 1.1 XSD；抽样轨迹与地图候选重合；换乘和不连续覆盖不产生错误直线。

### M7：完成度与发布

- 完成加载、空白、失败、取消、重试和破坏性确认体验。
- 完成键盘、焦点、对比度、屏幕阅读标签和非颜色编码检查。
- 对大型城市地图、搜索、CSV 和导出做性能基准与优化。
- 完成应用数据目录、日志轮转、备份/恢复和数据库迁移演练。
- 完成 macOS 与 Windows PowerShell 7 安装/启动说明；可复现 PyInstaller 安装产物已进入独立发布工作流，代码签名、公证和自动更新仍属于后续范围。
- 用真实代表性数据执行 Playwright 全流程与人工地图抽检。

**验收**：满足下方 v1.0 完成标准，且没有未说明的阻断缺陷。

## 3. 测试矩阵

| 层 | 重点 |
|---|---|
| 领域单元 | 名称规范化、候选评分、edge 顺序、覆盖去重 |
| 几何属性 | 正反可逆、端点连续、点间距、坐标范围、稳定输出 |
| 导入契约 | CPTOND 字段变化、CRS 缺失、坏几何、部分文件、回滚 |
| 数据库 | 外键、唯一约束、迁移前后、FTS/RTree 同步、事务失败 |
| API | schema、错误码、分页、并发更新、过期 candidate digest |
| 前端组件 | 表单依赖、审核状态、键盘导航、错误和空白状态 |
| E2E | 首次设置、手动行程、环线选择、CSV 修复、两种 GPX 导出 |
| 兼容抽检 | 生成文件通过 XSD，并在支持 GPX 1.1 轨迹导入的目标应用中人工抽检；Fog of World 作为固定实机回归样例 |

代表性拓扑夹具至少包括：

- 普通双向线 A–B–C–D。
- 起终点反向的 D–B。
- 环线的短弧/长弧两个候选。
- 主线与支线共享 A–B 后分叉。
- 换乘站在两条线路拥有多个 route_stop。
- 同城同名但空间分离的两个站。
- 断裂 MultiLineString、站点偏离、sequence 非单调等坏数据。

## 4. v1.0 完成标准

只有同时满足以下条件，才能把“完成整个应用”的目标标记为完成：

### 功能

- CPTOND-2025 真实数据导入、质量报告和至少两个代表性城市验收完成。
- 手动表单与地图选站都能创建、确认并保存行程。
- CSV 上传、审核、修复和事务提交完整可用。
- 行程列表、详情、筛选、编辑/重算和删除完整可用。
- journey/coverage 两种 GPX 导出完整可用。

### 正确性

- 普通、反向、环线、支线、换乘和同名站场景均有测试。
- 所有歧义必须确认；阻断性质量问题不能导出。
- 预览、保存、再次打开和导出的 edge 集合一致。
- GPX 通过官方 1.1 XSD 与应用的几何校验。

### 体验

- 数据未就绪、导入中、失败、空列表和网络/API 错误都有明确界面。
- 核心流程支持键盘并通过基础可访问性检查。
- 桌面和窄屏视口完成 E2E 验收，地图不遮挡主要操作。
- 危险操作可确认，长任务可观察、可取消或安全重试。

### 工程与交付

- 后端 lint/type/test、前端 lint/type/test/build 和 Playwright 全绿。
- 生产模式以单一、文档化命令在 `127.0.0.1` 启动。
- 新环境安装、数据导入、备份恢复、升级迁移和 GPX 兼容应用导入说明齐全。
- 不提交完整第三方数据、密钥、本地数据库或用户旅行记录。
- 已知限制和所有剩余非阻断问题被记录。

## 6. 铁路扩展路线

铁路路线同样按可验收纵向能力组织。完成状态与实机证据集中记录在本页“当前进度”；Fog of World 是固定兼容性回归样例，不限定铁路 GPX 的目标应用范围。

### R0：长三角铁路 POC

- 准备上海、江苏、浙江、安徽范围的 OSM PBF，并验证跨省边界连通性。
- 固定 OpenRailRouting/GraphHopper 版本，建立中国铁路初始 Profile。
- 支持手动输入有序站序，返回最多三个带评分和警告的候选。
- 在地图展示候选，并从确认候选生成单条铁路 GPX。
- 验证上海虹桥—南京南、上海虹桥—杭州东、上海—苏州、上海虹桥—合肥南。

**验收**：至少覆盖高速、普速、跨省、枢纽和替代路径；候选地图与 OSM 铁路走廊人工核对；GPX 通过 XSD 并可导入支持 GPX 1.1 轨迹的应用；记录 PBF、graph、Profile 与几何哈希。Fog of World 作为固定实机样例。

### R1：Provider、共享领域与单条行程

- 增加 MetroProvider/RailwayProvider/TimetableProvider 接口。
- 迁移 `journey_leg.transport_mode`、铁路数据版本、站点、站序和 edge snapshot。
- 实现铁路数据状态、导入、站点搜索和 discriminated path preview API。
- 实现车次录入、手动站序、地图选线、候选确认和铁路行程再次打开。
- 实现 OpenRailRouting sidecar 探测、超时、错误恢复和 loopback 限制。

**验收**：铁路预览、保存、再次打开和导出的几何哈希一致；sidecar 缺失不影响 metro-only 模式；迁移前数据库可升级和回滚。

### R2：统一 CSV、行程管理与混合导出

- 扩展 CSV 的 `mode`、`travel_date`、`train_no`、`train_type`、`via_stations` 和 `route_hint`。
- 实现铁路站名审核、站序调整、候选选择和事务提交。
- 在行程列表、筛选、编辑和删除中统一 metro/rail leg。
- 按地铁 25 米、铁路 200 米默认策略生成单模式或混合模式 GPX。
- 实现同一铁路图版本内的 coverage 去重和跨版本警告。

**验收**：混合 CSV 可审核提交；地铁与铁路行程共同导出且不产生错误直线；旧 v1.0 CSV 保持兼容。

### R3：全国图、版本更新与运维

- 从区域图扩展到中国 PBF，记录构建时间、峰值 RAM、磁盘和查询延迟。
- 在新目录构建 graph，运行固定样本后原子切换 active 版本。
- 建立车站别名库、枢纽人工修正规则和高铁/普速 Profile 校准样本。
- 支持数据/图/Profile 版本并存、差异报告和显式重算。
- 完成 OSM 署名、ODbL 分发审查、备份恢复和故障演练。

**验收**：全国代表性样本通过且资源要求有文档；图切换失败可回退；旧铁路行程在无旧 sidecar 的情况下仍可从快照导出。

### R4：可选授权时刻表 Provider

- 只接入许可、稳定性、版本和缓存边界明确的数据源。
- Provider 不得改变用户已确认的历史几何；更新只生成新候选。
- 不把 12306 爬虫或受限制的高德缓存作为完成条件。

**验收**：完成来源许可审计、失败降级、版本追踪和手动 Provider 回退。R4 不阻塞铁路首版完成。

### 当前关闭条件

铁路首版关闭条件已满足：真实铁路 GPX 已通过 XSD 与 Fog of World 固定实机样例，`Transit2GPX` 名称迁移与全部质量门禁已完成。R4 仍保持独立且不阻塞。
