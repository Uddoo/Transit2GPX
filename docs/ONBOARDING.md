# 首次使用向导

向导位于 `/setup`，也可以从“数据与设置 → 打开首次使用向导”进入。新安装打开应用根地址时自动进入；已有就绪数据或行程的安装不会被强制打断。

## 使用流程

1. **环境检查**：检查本地服务、数据库迁移版本、数据目录写入权限和可用空间。阻断项未解决时不能继续确认环境；空间不足会给出提示。安装包不要求用户额外安装 Node.js 或 uv。
2. **地铁数据**：提供 CPTOND 和 46 城兼容来源入口，填写解压目录后复用现有持久化导入任务。显示进度、取消、失败原因和重试入口；刷新页面后保留步骤、目录及导入状态。
3. **铁路服务（可选）**：填写已构建的图目录、图版本、对应 PBF，可在高级设置中指定 Java 和 JAR。检查 Java 17+、文件与版本身份，后台启动或复用匹配的本机服务；随后单独导入车站索引。服务启动成功与车站索引就绪分别展示，只有两者满足才能标记铁路可用。
4. **开始使用**：汇总实际可用的交通方式，至少有一种就绪后才能完成。可以跳过铁路或稍后设置；跳过不会被当作数据就绪。

向导不自动下载或构建全国铁路图；缺少数据与服务文件时提供仓库内的准备说明。目录与文件使用本机路径输入，支持粘贴带引号的路径。

## 恢复与故障处理

- 步骤、完成/跳过状态、地铁目录和铁路配置保存到本地 `app_meta`，不上传到外部服务。
- 向导保存的铁路选项作为下次启动默认值；显式启动参数与环境变量优先，这些字段在向导内不可改写。
- 铁路启动与校验运行在独立线程，重复启动请求不会并行启动多个进程。应用关闭时取消未完成的启动并停止自己拥有的 Java 进程；复用的外部服务不由应用终止。
- 铁路步骤定期读取服务状态，服务断开或身份变化时重新显示故障；错误说明覆盖缺少 Java/文件、版本不匹配、启动超时及日志排查入口。
- 检查或提交期间禁用步骤切换；从浏览器离开后，不会在异步检查完成时把用户重新带回旧步骤。
- 已有地铁数据、铁路快照与行程使用原有质量门禁与不可变快照规则。

## API

- `GET /api/v1/setup`：步骤、首次运行判断、实际数据状态、服务状态及当前配置。
- `PATCH /api/v1/setup/progress`：保存步骤、目录、跳过或完成状态；完成前重新验证环境与可用数据。
- `GET /api/v1/setup/checks`：环境检查。
- `POST /api/v1/setup/rail/check`：只检查铁路草稿配置，不保存或启动。
- `POST /api/v1/setup/rail/start`：保存允许修改的配置，返回 `202`，后台启动并可轮询状态。

地铁数据和车站索引导入继续使用已有 `/data/imports`、`/rail/data/imports` 接口及持久化任务执行器。向导没有新增数据库迁移。

设计稿使用内置 Image Gen 生成，界面控件与文字由 React/CSS 实现，没有使用整张设计图替代界面。设计简报为：完整的四步 Transit2Fog 首次使用向导，沿用现有品牌与导航，展示可验证的环境检查、数据导入、铁路启动、恢复和失败状态；不增加营销模块或虚构指标。

已使用 `view_image` 对照设计稿与浏览器截图，核对布局、文字层级、色彩、步骤状态、按钮、表单及窄屏换行。保留了既有导航图标与品牌副标题；实现额外提供数据准备链接、全部检查项及日志折叠区，磁盘空间和就绪数量来自实际接口。铁路错误截图使用缺少 Java 的模拟响应，其余运行验证使用隔离数据库与文件副本。

内置浏览器返回 `Browser is not available: iab`，使用项目 Playwright Chromium 验证。桌面按设计稿原尺寸 1505×1045 检查，窄屏为 390×844。真实联调使用合成地铁 Shapefile 和已有 Cologne 铁路样例的隔离副本，验证空库导入、Java 21 启动、身份校验、车站索引、完成设置、重启恢复及自有进程清理；不代表重新验证全国铁路数据。

2026-09-28 验证结果：`make check` 通过（121 个后端测试、17 个前端测试，后端覆盖率 87%）；32 个桌面/手机浏览器测试及 1 个仓库全栈测试通过。另完成真实 Java 21 + Cologne 样例的隔离联调，结果见 [验证记录](design/onboarding/verification.json)。入口 JavaScript 约 284 KB，向导独立按需加载，符合 350 KB 构建预算。

首屏文案核对：保留主标题、四步名称、环境检查说明及主操作文案；铁路步骤使用“填写本机路径”匹配实际输入方式，加入准备说明和日志入口。动态磁盘空间、数据数量及失败原因来自实际接口。布局、字号、色彩、控件层级和窄屏布局均已对照确认；未发现横向溢出或运行错误。
